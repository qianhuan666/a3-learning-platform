## UI Rules Learned From Fixes

- Buttons should either change state, navigate, call an API, or write telemetry; avoid purely decorative fake buttons in student flows.
- The first desktop viewport should fit without page-level overflow at 1366 x 900.
- Student-end shell now uses a 90% visual scale on a fixed, inverse-sized canvas to better match non-fullscreen browser windows across Chrome/Edge-like browsers.
- Card content should not be packed to the exact edge. Leave visible breathing room even when all content technically fits.
- Important labels and metrics should not ellipsize. Prefer smaller spacing or a clearer grid before hiding values.
- If a card contains variable-length content, use internal scrolling or reduce sample count rather than letting text exceed the border.
- Header actions and topbar utilities should align to the far right in their local group.
- Links under a card list should align with the list item left edge, not the outer card border.
