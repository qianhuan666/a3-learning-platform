## 一、项目当前状态

### 1.1 基本信息

| 项目 | 数值 |
|------|------|
| 总文件数 | 70 个（不含 node_modules） |
| 数据库表 | 39 张表 + 1 视图 + 30+ 索引 |

| API 端点 | 37 个（全部可用） |

### 1.2 整体评价

项目建立了一个**扎实的学生端平台**：39 张表、完整的 OCR 资源管道、LLM 驱动的智能辅导、目标模式系统。但愿景中的**多智能体系统、诊断入口、动态画像引擎、教师端**尚未构建。

## 三、未开发功能（按优先级排列）

### 🔴 关键缺失

| 功能 | 说明 | 影响 |
|------|------|------|
| **诊断测试系统** | 无 `diagnosis_question/record` 表，无诊断 API，无诊断页面 | 阻断「诊断→画像→计划」闭环入口 |
| **多智能体系统** | 7 个智能体中仅辅导智能体可用，无 agent_log 表，无编排框架 | 核心赛题要求缺失 |
| **动态画像引擎** | 画像分数为静态种子数据，不随学习行为更新 | 画像失去「动态」意义 |
| **教师端全部页面** | 6 个页面（首页/课程管理/资源管理/审核/班级学情/学生详情）全未实现 | 缺少一个重要利益方 |

| 功能 | 说明 |

## 四、后端后续开发计划

### Phase 1：诊断与画像闭环（2-3 天）

**目标**：打通「诊断测试 → 画像生成 → 计划推荐」入口链路

```
新增表:
├── diagnosis_questions        # 诊断题（按知识点、难度分级）
└── diagnosis_records          # 诊断记录（学生答案 + 评分）

新增 API:
├── GET  /api/diagnosis/questions?courseId=&difficulty=     # 获取诊断题
├── POST /api/diagnosis/submit                              # 提交诊断结果
├── POST /api/profile/generate                              # 基于诊断生成画像
├── GET  /api/profile/:studentId                            # 查询学生画像（已有，需完善）
└── POST /api/profile/update                                # 学习行为触发画像更新

改造:
├── student_profile_scores 从静态 → 动态计算
└── 画像雷达图从硬编码 SVG → ECharts 数据驱动
```

### Phase 2：计划智能引擎（1-2 天）

**目标**：从手动计划 → AI 自动生成 + 动态调整

```
新增 API:
├── POST /api/plans/generate      # 基于画像 + 目标模式生成周计划
└── POST /api/plans/adjust        # 基于最近表现动态调整计划

改造:
├── buildStudentPayload 注入计划生成理由
└── 前端 PlanPage 显示「AI 生成」vs「手动创建」标识
```

### Phase 3：RAG 知识库检索（2-3 天）

**目标**：辅导从「LLM 凭空回答」→「基于课程知识点检索增强」

```
新增表:
├── knowledge_chunks             # 知识块（定义/例题/常见错误）
└── knowledge_embeddings         # 向量嵌入（pgvector 或外部 API）

新增 API:
├── GET /api/knowledge/search?q=&limit=     # 知识库检索
└── GET /api/tutor/related-resources        # 辅导相关资源推荐

改造:
├── llm-client.cjs 注入 RAG 检索结果到系统提示词
└── buildTutorAnswer 优先使用知识库内容
```

### Phase 4：教师端（暂缓）

**目标**：恢复教师端功能（当前数据库已删除教师数据，需重建）

> 当前产品方向优先聚焦学生端闭环。教师端会引入教师账号、班级归属、资源审核与多页面权限体系，短期内暂缓，避免分散学生端智能学习主线。

```
新增页面（前端）:
├── 教师首页         # 班级概览、待审核、薄弱知识点
├── 课程管理页       # 章节/知识点 CRUD
├── 资源管理页       # 上传/编辑/删除/标签管理
├── 资源审核页       # 审核 AI 生成资源
├── 班级学情页       # 掌握度统计、进度统计、风险学生
└── 学生详情页       # 学生画像、学习计划、学习报告

新增 API:
├── GET    /api/teacher/dashboard                    # 教师首页数据
├── GET    /api/teacher/class/:id/overview           # 班级学情
├── GET    /api/teacher/student/:id/detail           # 学生详情
├── POST   /api/resources/:id/review                 # 资源审核
├── GET    /api/reports/class/:classId               # 班级报告
└── POST/PUT/DELETE /api/courses/:id/knowledge-points # 知识点管理
```

### Phase 5：学生端多智能体协同与可解释闭环（3-5 天）

**目标**：先围绕学生端实现可演示、可追踪的多智能体协同流程，让诊断、画像、知识检索、资源推荐、计划生成、智能辅导和学习评估形成可解释闭环。第一版采用确定性编排 + 数据库规则输出，后续再逐步增强 LLM 参与比例。

```
新增表:
└── agent_task_logs             # 智能体任务步骤日志

新增 API:
├── POST /api/agents/run              # 执行智能体协同流程
├── GET  /api/agents/logs/:taskId     # 查看智能体过程日志
└── GET  /api/agents/status           # 各智能体运行状态

智能体实现:
├── 画像分析智能体     # 基于学习数据更新画像维度
├── 课程知识智能体     # 维护知识点图谱
├── 资源推荐智能体     # 基于薄弱点匹配资源
├── 资源评审智能体     # 自动质量检查
├── 规划智能体         # AI 生成个性化学习计划
├── 辅导智能体         # ✅ 已实现
└── 评估智能体         # 生成学习评估报告

学生端展示:
├── 学习计划/学习报告页展示“智能体分析过程”
├── 展示每个智能体的输入摘要、输出结论和建议动作
└── 最终输出下一步学习任务、推荐资源、薄弱知识点和调整理由
```
