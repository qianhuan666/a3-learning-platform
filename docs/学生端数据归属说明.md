# 学生端数据归属说明

本文按页面说明：哪些内容应直接存入数据库，哪些内容由后端/API 根据数据库记录计算或推理，哪些只是前端交互状态。

## 1. 学习首页

存入数据库：

- 学生、课程、权限：`app_users`、`courses`、`user_accounts`、`account_portal_permissions`
- 今日学习任务：`study_plans`
- 今日任务清单：`learning_tasks`
- 推荐资源：`learning_resources`、`student_resource_recommendations`
- 每日学习指标：`learning_metric_daily`
- 按钮/入口使用记录：`student_activity_events`

后端计算/推理：

- 今日学习时长：取最近一天 `learning_metric_daily.study_minutes`
- 总体学习进度：优先取最近一天 `completion_rate`，否则按任务完成数计算
- 本周学习时长：汇总最近指标的 `study_minutes`
- 平均正确率：平均 `accuracy_rate`
- 推荐下一步：可由薄弱知识点、推荐资源和未完成计划综合排序

前端状态：

- 当前页面、推荐下一步的轮换序号、按钮 hover/active 状态

## 2. 学习画像

存入数据库：

- 六维能力与年级平均：`student_profile_scores`
- 知识点/章节掌握：`knowledge_mastery`
- 每日学习指标：`learning_metric_daily`
- 画像按钮使用记录：`student_activity_events`

后端计算/推理：

- 雷达图：由 `student_profile_scores.current_score` 生成
- 优势与待提升：按维度分数排序，低分维度进入待提升，高分维度进入优势
- 近期变化趋势：比较相邻日期指标或知识点分值变化
- 学习习惯分布：正式数据接入后建议由学习计划完成率、作业提交时延、错题整理次数等推理

前端状态：

- 是否展开画像解读、是否展开全部知识点、是否展开趋势详情

## 3. 学习计划

存入数据库：

- 计划任务：`study_plans`
- 任务完成项：`learning_tasks`
- 调整建议/提醒：`intervention_suggestions`
- 用户点击调整、应用调整、查看周详情：`student_activity_events`
- 用户主动新增、删除、切换日期后的计划仍以 `study_plans.plan_date` 为准，前端只保留当前选择日期和表单草稿

后端计算/推理：

- 本周目标完成度：按 `study_plans.status` 或 `learning_tasks.done` 计算
- 计划说明：由任务类型、顺序、薄弱点和学习规律模板生成
- 调整原因：由近期正确率、完成率、薄弱知识点触发
- 默认打开日期：如果前端未指定日期，API 选择数据库里最近有计划的日期，避免演示数据因日期滚动变成空页

前端状态：

- 调整面板展开状态、开关选中状态、周详情展开状态
- 当前日期控件值、新增任务表单草稿、创建/删除后的提示文案

## 4. 资源推荐

存入数据库：

- 资源库：`learning_resources`
- 学生-资源推荐关系：`student_resource_recommendations`
- 资源点击/筛选/换批记录：`student_activity_events`

后端计算/推理：

- 资源排序：按 `match_score`、薄弱点、偏好和近期使用行为排序
- 推荐依据：由画像、错题、学习时段和资源完成率生成
- 难度星级：当前演示从资源 metadata 或匹配分推导

前端状态：

- 当前筛选项、换批偏移量、最近一次资源动作提示

## 5. 智能辅导

存入数据库：

- 会话列表：`chat_sessions`
- 每轮对话消息：`chat_messages`
- 当前会话引导步骤：`chat_guidance_steps`
- 快捷动作记录：`chat_action_logs`
- 新对话、加载更多、清空历史等按钮行为：已有 `chat_action_logs`，通用事件也可写入 `student_activity_events`

后端计算/推理：

- AI 回复内容：当前由 `buildTutorAnswer` 根据输入和动作类型生成，后续可替换为模型服务
- 引导步骤：由 AI 回复或辅导策略生成
- 会话摘要：由最近一轮回复截取或后续由模型总结

前端状态：

- 输入框内容、忙碌状态、当前加载的会话数量、滚动位置

## 6. 学习报告

存入数据库：

- 学习日报：`learning_metric_daily`
- 知识掌握：`knowledge_mastery`
- 画像分数：`student_profile_scores`
- 老师/系统建议：`intervention_suggestions`
- 导出、切换报告、查看详情：`student_activity_events`

后端计算/推理：

- 周/月/学期汇总：按时间窗口聚合 `learning_metric_daily`
- 正确率趋势：按日期绘制 `accuracy_rate`
- 错题类型分布：正式接错题表后由错题分类聚合；当前演示为静态占位
- 老师评语建议：可由老师端写入，或由系统根据薄弱项辅助生成草稿

前端状态：

- 当前报告 tab、当前展开的详情块、导出文件的浏览器下载动作

## 7. 学习会话闭环

存入数据库：

- 每次从首页、学习计划、资源推荐进入学习：`student_learning_sessions`
- 完成标准：`student_learning_sessions.completion_definition`
- 目标时长、实际完成时长、完成分数、完成原因、结果摘要：`target_minutes`、`completed_minutes`、`completion_score`、`completion_reason`、`outcome`
- 学习计划状态联动：`study_plans.status`
- 资源使用联动：`student_resource_usage`
- 目标模式进度联动：`student_goal_modes.progress`、`student_goal_modes.metrics`
- 报告指标联动：`learning_metric_daily`
- 跨模块同步事件：`sync_events`

后端/API 计算或推理：

- 完成分数默认值：根据目标时长、实际完成时长和状态计算；正式题目接入后可由练习得分覆盖
- 完成率：同一天 `study_plans` 完成数 / 总数
- 日报时长增量：由完成接口统一写入，避免前端自行累计
- 目标模式进度增量：由完成状态和完成分数折算

前端状态：

- 当前打开的学习上下文、按钮 busy 状态、输入框草稿、聊天窗口滚动位置
- 前端可以临时显示“正在学习/已暂停/已完成”，但真实状态以 `student_learning_sessions.status` 为准
