# Resource Integration Foundation

This document defines the database layer prepared before importing real course resources.

## Purpose

The app should not put uploaded PDFs, courseware, notes, question banks, and distilled AI summaries into one loose `metadata` field. The database now separates:

- Resource source and import batch
- Course knowledge map
- User-facing resource cards
- Resource versions and parsed chunks
- Distilled summaries, misconceptions, practice plans, and tutor context
- Question items and student attempts

## Core Tables

| Table | Purpose |
| --- | --- |
| `resource_sources` | Where resources come from: internal seed, user upload, courseware, textbook, paper, web, question bank. |
| `resource_ingestion_batches` | One import run, with status and counts. |
| `course_knowledge_points` | Normalized course knowledge graph nodes. |
| `learning_resources` | User-facing resource cards used by the frontend. |
| `resource_knowledge_links` | Many-to-many mapping between resources and knowledge points. |
| `learning_resource_versions` | Source/version record for each resource. |
| `resource_chunks` | Parsed searchable chunks for RAG/tutor/recommendation. |
| `resource_ocr_jobs` | Local OCR runs for scanned PDFs, including page range, progress, confidence, and errors. |
| `resource_distillations` | Derived summaries, outlines, misconceptions, practice plans, recommendation profiles, tutor context. |
| `question_items` | Structured exercise/question records. |
| `student_question_attempts` | Student answer attempts and mistake tags. |

## Import Flow

1. Create or reuse a `resource_sources` row.
2. Create a `resource_ingestion_batches` row with `status = running`.
3. Insert/update `learning_resources` for visible cards.
4. Insert `learning_resource_versions` for each imported file/version.
5. Parse content into `resource_chunks`.
6. Map chunks/resources to `course_knowledge_points` through `resource_knowledge_links`.
7. Write distilled outputs to `resource_distillations`.
8. Extract exercises into `question_items` when applicable.
9. Mark the batch `completed` or `failed`.

## Frontend Boundary

The existing frontend should continue to read `learning_resources` and `student_resource_recommendations` for display. The new resource tables are backend/data-layer inputs that can later improve:

- Resource search and filtering
- Recommendation reasons
- AI tutor context
- Learning plan generation
- Report weakness and mistake analysis

## Local Resource Directory

User-provided PDFs are kept in:

```text
D:\A3\ziyuan
```

The project does not copy these files into source-controlled folders and does not store PDF binaries in PostgreSQL. The `.gitignore` excludes `ziyuan/`. Database records keep only metadata such as relative path, checksum, page count, text-layer state, OCR requirement, parsed chunks, and derived summaries.

Current local policy:

- Only China-sourced resources should be added to the active demo dataset.
- China MOOC videos are link-only resources; the app redirects to the public platform page and never downloads or stores videos.
- PDFs without a text layer are registered as resources and marked `ocrRequired=true`; OCR is a later pipeline step, not a blocker for opening the original PDF.
- PDFs with extractable text are split into `resource_chunks` automatically.

## Import Tooling

Run from the project root:

```powershell
node tools\ingest-local-pdf-resources.cjs
```

Optional environment variables:

- `LOCAL_RESOURCE_DIR`: override the local PDF directory.
- `A3_PYTHON`: override the Python executable used for PDF parsing.

The importer uses `tools\extract-pdf-metadata.py`, upserts `resource_sources`, `resource_ingestion_batches`, `learning_resources`, `learning_resource_versions`, `resource_chunks`, `resource_distillations`, and `student_resource_recommendations`.

## OCR Tooling

Scanned PDFs are OCRed locally with Poppler `pdftoppm` plus `tesseract.js`. OCR writes:

- `resource_ocr_jobs`: one row per OCR run.
- `resource_chunks`: page-level searchable chunks with `metadata.source = "ocr"`.
- `learning_resources.metadata`: `ocrStatus`, `ocrPagesDone`, `ocrChunkCount`, `ocrAverageConfidence`.
- `learning_resource_versions.raw_metadata`: OCR progress and latest job id.
- `resource_distillations`: a refreshed summary describing OCR readiness.

Recommended incremental run:

```powershell
cd D:\A3
node tools\ocr-local-pdf-resource.cjs --all-local --pages 1 --max-pages 1 --limit 4
```

Run a specific resource/page range:

```powershell
node tools\ocr-local-pdf-resource.cjs --resource-code LOCAL-PDF-36D3A05BB2C9 --pages 10-12 --max-pages 3
```

Defaults are conservative on purpose. Full textbooks are hundreds of pages, so run OCR in page ranges and verify quality before bulk processing. The default OCR language is `chi_sim`; use `--lang chi_sim+eng` only when the source contains substantial English.

For full local batch OCR after the four PDFs have been registered:

```powershell
node tools\ocr-all-local-pdfs.cjs --chunk-size 10 --dpi 150
```

After OCR is complete, run the local learning distillation pass:

```powershell
node tools\distill-ocr-learning-resources.cjs
```

The distillation pass is local and heuristic. It does not call an AI model. It writes `summary`, `outline`, `key_points`, `practice_plan`, and `tutor_context` rows into `resource_distillations`, updates `learning_resources.metadata.distillationStatus`, and creates short essay-style reading prompts in `question_items` with `metadata.source = "local_ocr_distillation"`.

## Active API Surface

- `GET /api/resources`: resource list with filter, sort, keyword, and database-backed recommendation fields.
- `GET /api/resources/:id`: resource detail with source, file metadata, OCR job state, chunks, distillations, and linked questions.
- `GET /api/resources/:id/file`: permission-checked local PDF response or external link redirect.
- `GET /api/questions`: structured questions for a course or resource.
- `POST /api/question-attempts`: records a local answer attempt and returns score plus solution.
- `PATCH /api/plans/:id/status`: updates plan task status when a student starts or reviews a task.
- `GET /api/goal-modes/:modeKey/learning-module`: target-mode learning module summary with milestones, resources, OCR chunks, and questions.
- `POST /api/tutor/messages`: stores the student message, retrieves same-course OCR snippets from `resource_chunks`, stores assistant citations in `chat_messages.metadata.citations`, and returns the refreshed tutor payload.
- `POST /api/tutor/actions`: runs quick tutor actions against the latest student message and stores the same citation metadata when OCR context is found.

## Tutor OCR Context

The tutor module is local-context aware but still heuristic. It does not call an AI model. For each student question or quick action, the API:

1. Extracts math keywords such as `函数`, `微分`, `导数`, `二重积分`, `换元`, or `特征值`.
2. Searches same-subject and same-grade OCR chunks in `resource_chunks`.
3. Ranks正文教材 pages ahead of contents, preface, and exercise-book pages.
4. Writes all selected citations into `chat_messages.metadata.citations`.
5. Returns the payload to the frontend, which displays the top two citations inside the assistant bubble.

This keeps the chat history self-contained: replaying an old session does not need to rerun OCR search to show the original source evidence.
