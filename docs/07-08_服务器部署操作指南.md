# A3 学习平台服务器部署操作指南

更新时间：2026-07-07  
适用范围：学生端 Web 应用、Node/Express 后端、PostgreSQL 数据库、Nginx 反向代理  
推荐部署方式：单台 Linux 服务器部署，适合演示、答辩、小规模内测

## 1. 部署目标

把当前本地运行的 A3 学习平台部署到服务器，使队员或测试人员可以通过公网域名或服务器 IP 访问。

目标架构：

```text
浏览器
  |
  | HTTPS / HTTP
  v
Nginx
  |-- /              -> frontend/dist 静态文件
  |-- /api/*         -> Node 后端 http://127.0.0.1:3001
                         |
                         v
                    PostgreSQL a3_learning
```

当前项目特点：

- 前端：React + Vite。
- 后端：Node.js + Express。
- 数据库：PostgreSQL。
- 大模型接口：OpenAI-compatible 格式，当前可接 DeepSeek。
- 当前产品范围：学生端。
- 教师端暂缓，不作为本轮部署目标。

## 2. 服务器推荐配置

### 2.1 最低配置

适合个人测试或小范围演示：

- CPU：2 核。
- 内存：4 GB。
- 磁盘：40 GB。
- 系统：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS。

### 2.2 推荐配置

适合多人测试：

- CPU：4 核。
- 内存：8 GB。
- 磁盘：80 GB。
- 系统：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS。

### 2.3 端口规划

| 服务 | 端口 | 对外开放 | 说明 |
| --- | --- | --- | --- |
| Nginx HTTP | 80 | 是 | 首次访问或申请证书 |
| Nginx HTTPS | 443 | 是 | 推荐正式访问入口 |
| Backend API | 3001 | 否 | 只监听本机，由 Nginx 转发 |
| PostgreSQL | 5432 | 否 | 只允许本机访问 |

## 8. 初始化 PostgreSQL

### 8.1 启动 PostgreSQL

```bash
sudo systemctl enable postgresql
sudo systemctl start postgresql
sudo systemctl status postgresql
```

### 8.2 创建数据库和用户

进入 PostgreSQL：

```bash
sudo -u postgres psql
```

执行：

```sql
create database a3_learning;
create user a3_user with encrypted password '请替换为强密码';
grant all privileges on database a3_learning to a3_user;
alter database a3_learning owner to a3_user;
\q
```

测试连接：

```bash
psql -h 127.0.0.1 -U a3_user -d a3_learning
```

退出：

```sql
\q
```

### 8.3 导入数据库结构和初始数据

进入项目目录：

```bash
cd /opt/a3-learning-platform
```

执行 schema：

```bash
PGPASSWORD='你的数据库密码' psql -h 127.0.0.1 -U a3_user -d a3_learning -f database/schema.sql
```

执行 seed：

```bash
PGPASSWORD='你的数据库密码' psql -h 127.0.0.1 -U a3_user -d a3_learning -f database/seed.sql
```

执行 migration。至少确认当前打开过的迁移文件已执行：

```bash
PGPASSWORD='你的数据库密码' psql -h 127.0.0.1 -U a3_user -d a3_learning -f database/migrations/2026-05-24-tutor-real-storage.sql
```

如果 `database/migrations/` 目录里还有后续迁移文件，应按文件名时间顺序执行：

```bash
ls database/migrations
```

检查关键表：

```bash
PGPASSWORD='你的数据库密码' psql -h 127.0.0.1 -U a3_user -d a3_learning -c "\dt"
```

建议确认以下表存在：

- `user_accounts`
- `students`
- `study_plans`
- `learning_resources`
- `chat_sessions`
- `chat_messages`
- `student_activity_events`
- `student_learning_sessions`
- `agent_task_logs`

## 9. 配置环境变量

### 9.1 当前项目的配置读取方式

当前后端配置文件：

```text
backend/src/config.cjs
```

目前它会读取：

```text
frontend/.env
```

所以服务器部署时，需要在服务器上创建：

```text
/opt/a3-learning-platform/frontend/.env
```

注意：不要提交 `.env` 到 Git。

### 9.2 创建生产环境变量文件

```bash
cd /opt/a3-learning-platform
nano frontend/.env
```

示例：

```env
API_PORT=3001

PGHOST=127.0.0.1
PGPORT=5432
PGDATABASE=a3_learning
PGUSER=a3_user
PGPASSWORD=请替换为数据库强密码

LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=请替换为真实API_KEY
LLM_MODEL=deepseek-v4-pro
LLM_REASONING_EFFORT=high
LLM_MAX_TOKENS=4096

SESSION_DAYS=7
ALLOW_DEMO_ACCOUNT_FALLBACK=true

DEMO_STUDENT_ID=00000000-0000-0000-0000-000000000101
DEMO_COURSE_ID=00000000-0000-0000-0000-000000000301

LOCAL_RESOURCE_DIR=/opt/a3-learning-platform/ziyuan
```

说明：

- `API_PORT`：后端监听端口。
- `PG*`：PostgreSQL 连接信息。
- `LLM_*`：大模型配置。
- `LLM_MODEL`：建议使用 `deepseek-v4-pro` 或当前可用模型，不建议继续依赖即将弃用的旧模型名。
- `LOCAL_RESOURCE_DIR`：本地资源目录，如果不使用本地 PDF，可以留空或指向项目资源目录。

### 9.3 权限保护

```bash
chmod 600 frontend/.env
```

## 13. 配置 Nginx

### 13.1 创建站点配置

```bash
sudo nano /etc/nginx/sites-available/a3-learning-platform
```

如果使用域名，将 `server_name` 改为你的域名。没有域名时可以先写服务器 IP 或 `_`。

```nginx
server {
    listen 80;
    server_name 你的域名或服务器IP;

    root /opt/a3-learning-platform/frontend/dist;
    index index.html;

    client_max_body_size 20m;

    location /api/ {
        proxy_pass http://127.0.0.1:3001/api/;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式响应需要关闭缓冲
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 13.2 启用站点

```bash
sudo ln -s /etc/nginx/sites-available/a3-learning-platform /etc/nginx/sites-enabled/a3-learning-platform
```

如果默认站点冲突，可以移除默认站点：

```bash
sudo rm -f /etc/nginx/sites-enabled/default
```

检查配置：

```bash
sudo nginx -t
```

重载 Nginx：

```bash
sudo systemctl reload nginx
```


## 21. 常见问题排查

### 21.1 前端能打开，但 API 失败

检查：

```bash
curl http://127.0.0.1:3001/api/health
pm2 status
pm2 logs a3-backend --lines 100
sudo nginx -t
```

可能原因：

- 后端未启动。
- `frontend/.env` 数据库密码错误。
- Nginx `/api/` 转发配置错误。
- 防火墙或安全组未开放 80/443。

### 21.2 登录失败

检查：

```bash
PGPASSWORD='你的数据库密码' psql -h 127.0.0.1 -U a3_user -d a3_learning -c "select username, status from user_accounts;"
```

确认存在：

```text
student_demo
```

如果没有，重新执行 seed。

### 21.3 数据库连接失败

检查 `.env`：

```bash
cat /opt/a3-learning-platform/frontend/.env
```

检查 PostgreSQL：

```bash
sudo systemctl status postgresql
psql -h 127.0.0.1 -U a3_user -d a3_learning
```

### 21.4 智能辅导不能调用大模型

检查：

```bash
pm2 logs a3-backend --lines 100
```

确认：

- `LLM_API_KEY` 不为空。
- `LLM_BASE_URL=https://api.deepseek.com`。
- `LLM_MODEL` 是当前可用模型，例如 `deepseek-v4-pro`。
- 服务器可以访问外网。

如果没有配置大模型 Key，系统可能走 fallback，这是环境问题，不一定是代码问题。

### 21.5 流式响应不流式

检查 Nginx 配置中是否包含：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 3600s;
```

修改后执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 21.6 页面刷新 404

确认 Nginx 有：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

这是 React Router 前端路由必须配置的 fallback。

### 21.7 本地 PDF 或资源打不开

检查：

```bash
ls /opt/a3-learning-platform/ziyuan
```

确认 `.env`：

```env
LOCAL_RESOURCE_DIR=/opt/a3-learning-platform/ziyuan
```

如果资源目录不存在，需要上传资源文件或暂时只测试外部链接资源。

## 22. 安全注意事项

- 不要提交 `.env`。
- 不要把数据库密码、大模型 API Key 写入文档或代码。
- 服务器上不要开放 PostgreSQL 5432 到公网。
- 后端 3001 不直接对公网开放，只由 Nginx 转发。
- 生产环境建议将 `ALLOW_DEMO_ACCOUNT_FALLBACK=false`，但演示阶段可保留为 `true`。
- 建议定期备份数据库。
- 如果远端 Git URL 中包含 token，服务器多人共用时应改成 SSH key 或部署专用 token。

## 23. 推荐后续优化

当前部署可以直接支持演示和测试。后续如果要更规范，可以继续做：

- 将后端配置改为读取项目根目录 `.env` 或 `backend/.env`，不再依赖 `frontend/.env`。
- 增加 `ecosystem.config.cjs`，统一 PM2 配置。
- 增加一键部署脚本，例如 `scripts/deploy.sh`。
- 增加 migration 执行记录表。
- 使用对象存储管理 PDF 和图片资源。
- 使用独立数据库服务器或云数据库。
- 增加 CI/CD 自动构建和部署。
